# Инструкция руководителя

Модуль технического обслуживания ООО НПО «Спецмонтаж». Адрес: https://specmontazh.online

## Вход

Откройте адрес в браузере, введите логин и пароль, нажмите «Войти». Учётную запись выдаёт администратор. После 8 часов бездействия система попросит войти заново. Кнопка «Выйти» — в верхней части страницы.

Слева — меню: **Задания**, **Объекты**, **Регламенты**, **Шаблоны**, **Отчёт**.

## Порядок работы

1. Завести объект, его системы и оборудование.
2. Проверить чек-лист в разделе «Шаблоны».
3. Создать регламент и активировать его.
4. Назначить инженера на созданное задание.
5. Проверить результат и принять ТО или вернуть на доработку.
6. Выгрузить отчёт.

## 1. Объекты, системы и оборудование

**Объекты → «+ Добавить объект».** Заполните название, адрес, заказчика, контактное лицо и телефон.

Откройте карточку объекта:

- вкладка **«Системы» → «+ Добавить систему»**: название и тип (пожарная сигнализация, СОУЭ, охранная сигнализация, видеонаблюдение). Тип нельзя изменить, если у системы уже есть оборудование, регламенты или задания;
- вкладка **«Оборудование» → «+ Добавить оборудование»**: выберите систему, укажите название, тип, модель, серийный номер и расположение;
- вкладка **«История ТО»** — все задания по объекту.

**«Вывести из эксплуатации»** (у оборудования): устройство больше не попадает в новые задания, прежние результаты сохраняются. Если устройство входит в незавершённое задание, вывести его нельзя. При замене устройства выведите старое и добавьте новое.

**Архив** («Архивировать»): объект или система уходят в архив, их регламенты приостанавливаются. Архивировать нельзя, пока есть незавершённые задания — система покажет их список. Удалить можно только карточку без связанных данных.

## 2. Шаблоны чек-листов

**Шаблоны** — по одному на каждый тип системы. Пункт шаблона применяется либо ко всей системе, либо к каждому устройству нужных типов. Пункт можно сделать обязательным, изменить, удалить, переставить стрелками «Выше» и «Ниже».

Изменение шаблона действует только на новые задания: уже созданные не меняются.

## 3. Регламенты

**Регламенты → «+ Добавить регламент».** Выберите объект и систему, укажите название, ближайшую дату ТО и периодичность в месяцах. Регламент создаётся черновиком — задания по нему не появляются.

- **«Активировать»** — регламент начинает действовать. Задание создаётся автоматически за 5 дней до срока; если срок ближе 5 дней, задание создаётся сразу. Активировать нельзя, если чек-лист получается пустым: в шаблоне нет пунктов для всей системы, а у системы нет оборудования подходящих типов.
- **«Приостановить»** — новые задания не создаются, пропущенные не накапливаются.
- **«Возобновить»** — нужно задать новую ближайшую дату, отсчёт пойдёт от неё.

Месяцы считаются от исходной даты: 31 января → 28 февраля → 31 марта. Дату и периодичность действующего регламента изменить нельзя: приостановите его и задайте новую дату при возобновлении.

## 4. Задания

**Задания** — список с поиском и фильтрами по объекту, инженеру и статусу. Вкладки: «Все задания», «Просрочено», «На проверке», «Отменённые».

Статусы задания:

| Статус | Что означает |
|---|---|
| Создано | инженер не назначен |
| Назначено | инженер назначен, работа не начата |
| В работе | инженер заполняет чек-лист |
| На проверке | результат передан вам |
| На доработке | вы вернули результат инженеру |
| Принято | ТО принято, результаты больше не меняются |
| Отменено | задание отменено с указанием причины |

В карточке задания:

- **«Назначить исполнителя» / «Сменить исполнителя»** — выбор из активных инженеров. Пока задание на проверке, сменить исполнителя нельзя: сначала верните его на доработку;
- **«Перенести срок»** — новый срок (не в прошлом) и причина. Исходный срок сохраняется, задание помечается «перенесён»;
- **«Отменить задание»** — с обязательной причиной;
- блок **«История задания»** — кто, когда и что менял.

Если работа выполнена позже исходного срока, в задании отмечается «Нарушение срока» — даже если срок переносили.

## 5. Проверка результата

Задание «На проверке» показывает результаты всех проверок, комментарии и общий комментарий инженера.

- **«Принять ТО»** — работа принята, результаты фиксируются. Замечания о дефектах не мешают приёмке: они сохранятся в результатах и в отчёте.
- **«На доработку»** — укажите, что требуется исправить. Инженер увидит ваш комментарий в задании.

**Частичный результат** (обязательный пункт отмечен «Не проверено») принять нельзя: верните задание на доработку или отмените его.

## 6. Отчёт

**Отчёт** — задания за период по исходной плановой дате, с фильтрами по объекту, типу системы, текущему исполнителю и статусу. В таблице: сроки, просрочка, нарушение срока, частичный результат, замечания, причины отмены и возврата.

**«↓ Выгрузить CSV»** — те же строки файлом для Excel: разделитель «;», кодировка UTF-8.

## Пользователи (администратор)

Раздел **«Пользователи»** виден только администратору.

- **«+ Добавить пользователя»**: ФИО, логин, роль (администратор, руководитель, инженер) и начальный пароль. Пароль сообщите сотруднику лично.
- **Сброс пароля**: откройте пользователя и введите новый пароль. Все его сеансы завершатся.
- **«Заблокировать»** — сотрудник сразу теряет доступ. Его задания остаются, переназначьте их другому инженеру.
- Последнего активного администратора нельзя заблокировать или сменить ему роль. Роль инженера нельзя сменить, пока на нём есть незавершённые задания.
